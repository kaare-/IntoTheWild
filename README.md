# Villmarks

A small wilderness MUD. The valley is already there: a brook, a still pool, a slope, a rock overhang, dry wood and berries under that rock, a pot, poison berries, mushrooms, an open pile, one heavy log, one loose stone on the slope at (2,0), two lumps of clay on the bank at (2,2), and one deer on the trail. People and external agents use the same rules. Rain soaks whatever the sky can reach. Bark on a frame supported at both ends is a roof; a half-finished frame is not. The same bark, with a dry branch, is tinder for a fire.

The simulation is a Rust library with no network, database, clock, or model calls. One Tokio and Axum process owns the valley. A TypeScript page and a Python client are players, not special cases. Design choices taken from EmpireMUD, Bunnyland, Aardwolf, and GemStone III are in [DESIGN.md](DESIGN.md). Nothing here is deployed.

## Run it

Rust 1.99.1 is pinned in `rust-toolchain.toml`. You need Node and Python 3.

```bash
cargo build -p villmarks-server
cd web && npm install && npm run build && cd ..
cargo run -p villmarks-server
```

The valley listens on [http://127.0.0.1:18431](http://127.0.0.1:18431). The action window is 20 seconds (`config/evening.toml`). Open a second browser tab and take a different name. `sessionStorage` keeps each tab's token.

```bash
python3 agent/play.py --name Linde
```

That client uses a scripted policy and no model key. To let an external model pick from the same allowed actions, set `VILLMARKS_MODEL_URL`, `VILLMARKS_MODEL_NAME`, and `VILLMARKS_MODEL_KEY`. The world does not wait on the model.

Useful flags:

```bash
cargo run -p villmarks-server -- --help
cargo run -p villmarks-server -- --manual          # advance with POST /v1/advance
cargo run -p villmarks-server -- --window-secs 2   # shorter windows
cargo run -p villmarks-server -- --data data/valley.sqlite
```

Delete the sqlite file to reseed the valley. A living file keeps the tuning it was born with. The web dev server, if you want it, is `npm run dev` in `web/` on port 47321 and proxies the API.

It is spoken as one stone: "A stone lies in contact with the ground here, in the open. The stone is dry. The sky is open above it. It is a found stone." In the arms, examine is one sentence: "A dry stone is carried by you, in the open, and it is a found stone." The id stays on the server. Branches and berries stay quantities.

Two lumps of clay lie on the bank at (2,2), on the valley floor beside the brook and the still pool. `gather clay` lifts one lump. `set clay` while you stand at a burning fire puts that lump on the ground. Four ticks later (`clay_ticks` in `config/evening.toml`), if the fire is still burning, the clay hardens into a bowl. While it is hardening, look says "A lump of clay is hardening in the fire." on every tick of that wait. The sentence stops when the bowl is there. `gather bowl` lifts it. `boil` with the bowl works the same as with the pot: the water is drunk, and the bowl is not used up. Unfired clay cannot boil water. If the fire is out when those four ticks are up, the clay stays soft. Someone outside sight does not see the clay. There is no kiln, no wheel, and no metal. The seeded pot stays under the rock.

`bind spear` spends one carried stone and one carried branch and leaves one spear in the arms. The stone and the branch are gone, and neither is copied onto the ground. The spear keeps one id. Holding that spear on a burning fire hardens the point after four ticks (`spear_ticks` in `config/evening.toml`). While the point is hardening, look says "The point of your spear is hardening in the fire." on every tick of that wait. The sentence stops when the point has hardened. The same id is still the spear. A nearby character reads "A spear with an unhardened point is carried by …" before that, and "A spear with a hardened point is carried by …" after. Look in the arms says "a spear with an unhardened point" or "a spear with a hardened point". On the ground, look says "A spear lies here. The point is not hardened." or "A spear lies here. The point is hardened." A spear left on the ground, or carried away from the fire, does not harden. A spear on the ground is the letter `j`.

`hunt` needs a hardened spear, and the deer on your cell or the next one. An unhardened spear is refused and does not wound the deer. On the deer's own cell the point brings it down. On the next cell the conditions are even enough for a recorded draw: the deer is killed, missed, or bolts. The same seed repeats that draw. A miss or a bolt leaves the deer alive and moved. A kill leaves the deer gone and one carcass on that cell. `gather carcass` lifts it. `eat carcass` is refused: "The carcass must be cooked." The carcass stays in the arms, and the hunger does not ease. `cook` at a fire is what turns the carcass into food. The result says the hunger word the body already uses. When the energy word also changes, it says that too: rested, tiring, or spent. When the energy word stays, it does not add an energy line. Someone who cannot see the deer does not see the kill. The spear is not used up.

Thirst rises every tick, whether or not anyone is here. Rain wets clothes and does not quench it. `drink` works in the brook or in the still pool at (2,1). ## An evening

Rain starts at tick 16. One person can still roof a frame before that if they take three branches and bark from under the rock and build on open ground. The open pile at (5,2) and the dry pile under the rock are the comparison. Two people can drag the log; one cannot.
